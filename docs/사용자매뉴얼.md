## 2. 설치와 실행 (인터넷 PC)

### 2.1 준비물

- 브라우저: Chrome 또는 Edge 최신 버전
- (방법 B만) Python 3.8 이상. 확인: 명령 프롬프트에서 `python --version`
  - 없으면 python.org에서 설치합니다. Windows 설치 화면에서 **Add python.exe to PATH**를 체크하세요.
  - 추가 패키지(pip install)는 필요 없습니다.

### 2.2 내려받기

```bash
git clone <저장소 주소>
cd allweneed
```

또는 GitHub의 **Code → Download ZIP**으로 받아 압축을 풉니다.

### 2.3 방법 A: 파일로 바로 열기

`dist/standalone.html`을 더블클릭합니다. 오른쪽 위 배지가 **예시 모드 · AI 미연결**이면 정상입니다.

### 2.4 방법 B: 실행 서버로 열기

```bash
python serve.py
```

Windows에서는 `start.bat`을 더블클릭해도 됩니다. 브라우저가 자동으로 `http://127.0.0.1:8080`을 엽니다. 실행 창에 이렇게 나오면 정상입니다.

```
22:10:05 실행 중: http://127.0.0.1:8080  (끝내려면 Ctrl+C)
22:10:05 AI: 꺼짐 (예시 모드) / 라이브러리: CDN(인터넷)
```

처음에는 사내 LLM이 꺼져 있어 예시 모드로 동작합니다. 사내 LLM 연결은 [4장](#4-사내-llm-연결)을 보세요.

- 끝내기: 실행 창에서 `Ctrl+C`
- 포트 바꾸기: `python serve.py --port 9000`
- 브라우저 자동 열기 끄기: `python serve.py --no-browser`

### 2.5 폴더 구조

| 경로 | 설명 | 고칠 일 |
|---|---|---|
| `dist/standalone.html` | 앱 화면 전체(한 파일) | 없음 |
| `serve.py` | 화면을 띄우고 사내 LLM 호출을 중계하는 서버 | OpenAI 호환이 아닌 LLM일 때만([4.5](#45-openai-호환이-아닌-사내-llm)) |

| `fetch_vendor.py` | 폐쇄망 반입용 라이브러리 내려받기 | 없음 |
| `vendor/` | 반입한 라이브러리 5개 | 없음 |
| `src/`, `build.py` | 원본 코드와 빌드 스크립트 | 기능을 고칠 때 |

## 3. 폐쇄망 설치

폐쇄망에서는 외부 CDN(PDF·Word·Excel 처리 라이브러리)과 웹 글꼴을 쓸 수 없습니다. 인터넷 PC에서 라이브러리를 받아 함께 반입합니다.

### 3.1 인터넷 PC에서 준비

```bash
python fetch_vendor.py
```

`vendor` 폴더에 다음 5개 파일이 생깁니다. 모두 공개 오픈소스 라이브러리이며 업무 자료는 들어 있지 않습니다.

| 파일 | 용도 | 라이선스 |
|---|---|---|
| `pdf.min.js`, `pdf.worker.min.js` | PDF 글자 읽기 | Apache-2.0 |
| `mammoth.browser.min.js` | Word(.docx) 글자 읽기 | BSD-2-Clause |
| `jszip.min.js` | PPT·HWPX 읽기, Word 내보내기 | MIT |
| `xlsx.full.min.js` | Excel 읽기·내보내기 | Apache-2.0 |

### 3.2 반입

저장소 폴더 전체(`vendor` 포함)와 Python 설치 파일을 **기관의 자료 반입 절차**에 따라 폐쇄망 PC로 옮깁니다. 프로그램 반입 승인이 필요한지 정보보호 담당에게 먼저 확인하세요.

### 3.3 폐쇄망 설정

`settings.example.json`을 복사해 `settings.json`을 만들고 `assets.offline`을 `true`로 바꿉니다.

```json
"assets": { "offline": true }
```

이렇게 하면 라이브러리를 `vendor` 폴더에서 읽고, 외부 글꼴 요청을 빼서 화면이 늦게 뜨지 않습니다(글꼴은 맑은 고딕으로 표시). 그다음 [4장](#4-사내-llm-연결)대로 사내 LLM을 연결하고 `python serve.py`로 실행합니다.

## 4. 사내 LLM 연결

> **Claude API로 쓰려면** 4.8을 보세요. 설정 파일 위치와 방법은 같고, `provider`와 API 키만 다릅니다.

### 4.1 바꿀 곳 한눈에

> **대부분은 `settings.json` 한 파일만 고치면 됩니다.** 코드 수정이나 다시 빌드할 필요가 없습니다. 고친 뒤에는 `serve.py`를 껐다 켜세요.

| 바꿀 것 | 파일 | 항목 | 예시 |
|---|---|---|---|
| ① 사내 LLM 사용 켜기 | `settings.json` | `llm.provider` | `"openai"` (끄기: `"none"`) |
| ② LLM 주소 | `settings.json` | `llm.base_url` | `"http://llm.example.internal:8000/v1"` |
| ③ 모델 이름 | `settings.json` | `llm.model` | `"사내-모델-이름"` |
| ④ 정밀 분석용 모델(선택) | `settings.json` | `llm.model_precise` | 더 큰 모델 이름. 비우면 ③과 같음 |
| ⑤ 인증 키(필요할 때) | `settings.json` 또는 환경변수 | `llm.api_key` / `REQAI_LLM_API_KEY` | 키를 파일에 두기 싫으면 환경변수 |
| ⑥ 추가 인증 헤더(필요할 때) | `settings.json` | `llm.extra_headers` | `{"X-Api-Client": "reqai"}` |
| ⑦ 한 번에 보낼 최대 크기 | `settings.json` | `llm.max_prompt_bytes` | 모델 컨텍스트에 맞게. [4.6](#46-모델과-크기-고르기) |
| ⑧ 응답 대기 시간 | `settings.json` | `llm.timeout_sec` | 느린 모델은 `600` |
| ⑨ 사내 인증서(https) | `settings.json` | `llm.ca_bundle` | `"C:/certs/internal-ca.pem"` |
| ⑩ 폐쇄망 라이브러리 | `settings.json` | `assets.offline` | `true` |
| ⑪ OpenAI 호환이 **아닌** API | `serve.py` | `call_llm()` 함수 하나 | [4.5](#45-openai-호환이-아닌-사내-llm) |

"OpenAI 호환"은 `POST {base_url}/chat/completions`에 `messages`를 보내고 `choices[0].message.content`로 답을 받는 방식입니다. vLLM, Ollama, LM Studio, TGI, LocalAI와 상당수 사내 LLM 게이트웨이가 이 방식을 지원합니다. 사내 LLM 담당 부서에 **"OpenAI 호환 Chat Completions API 주소와 모델 이름"** 을 물어보면 됩니다.

### 4.2 동작 구조

```
[브라우저]                         [serve.py]                       [사내 LLM]
 ① 민감정보를 토큰으로 가림
 ② 가린 자료 + 지시문  ──POST /api/llm──▶  ③ 주소·모델·키를 붙여  ──▶  /v1/chat/completions
                                            (키는 여기에만 있음)
 ⑤ 토큰을 원래 값으로   ◀────────────────  ④ 답 글자만 돌려줌    ◀──
    되살려 화면·문서에 표시
```

- 원래 이름·연락처는 브라우저 밖으로 나가지 않습니다. serve.py와 사내 LLM은 `[이름-1]` 같은 토큰만 봅니다.
- API 키는 serve.py에만 있고 브라우저로 보내지 않습니다.
- serve.py는 자료 본문이나 AI 답을 화면·파일에 남기지 않습니다(크기와 걸린 시간만 표시).

### 4.3 설정 예시

`settings.example.json`을 복사해 `settings.json`을 만든 뒤 `llm` 부분을 고칩니다.

**사내 LLM 게이트웨이(키 필요)**

```json
  "ca_bundle": "C:/certs/internal-ca.pem",
  "max_prompt_bytes": 200000

```

키는 파일 대신 환경변수로 넣는 것을 권장합니다.

```bat

python serve.py
```

```bash

```

**vLLM 서버**


### 4.4 연결 시험

```bash

```

정상이면 이렇게 나옵니다.

```

  base_url : http://10.0.0.5:8000/v1
  model    : 사내-모델-이름
  api_key  : 설정됨
```

그다음 `python serve.py`로 실행하면 화면 오른쪽 위 배지가 **사내 LLM 연결됨 · 모델 이름**(초록)으로 바뀝니다. 빨간 **사내 LLM 연결 안 됨**이면 배지에 마우스를 올려 이유를 보고 [8장](#8-문제-해결)을 참고하세요.

### 4.5 OpenAI 호환이 아닌 사내 LLM

사내 API 규격이 다르면 `serve.py`의 `call_llm()` 함수 **하나만** 고칩니다(★ 표시가 있는 함수). 이 함수는 프롬프트 글자를 받아 `(답 글자, 모델 이름)`을 돌려주면 됩니다. 화면 코드는 고칠 필요가 없습니다.

예를 들어 사내 API가 `POST /api/generate`에 `{"query": "..."}`를 받고 `{"result": {"answer": "..."}}`를 돌려준다면:

```python
def call_llm(cfg, prompt, tier="default", want_json=True):
    llm = cfg["llm"]
    body = {"query": SYSTEM_PROMPT + "\n\n" + prompt, "model": llm["model"]}
    out = http_json(cfg, llm["base_url"] + "/api/generate", body, timeout=llm["timeout_sec"])
    return out["result"]["answer"], llm["model"]
```

`http_json()`이 인증 키, 추가 헤더, 사내 인증서, 프록시 설정을 처리하므로 그대로 쓰면 됩니다. 연결 상태 확인(`health()`)은 `{base_url}/models`를 부르는데, 이 주소가 없어도 서버가 응답만 하면 연결된 것으로 봅니다.

### 4.6 모델과 크기 고르기

- **모델**: 지시를 잘 따르는 대화형(instruct/chat) 모델을 쓰세요. 한국어 성능이 좋고, JSON 형식으로 답할 수 있어야 합니다. `--check`의 3)이 "정상"이면 형식은 문제없습니다.
- **크기(`max_prompt_bytes`)**: 한 번에 보내는 지시문 + 자료의 최대 바이트입니다. 한글 1자는 약 3바이트입니다. 대략 **모델 컨텍스트 토큰 수 × 1.5** 정도로 잡고, 답을 쓸 자리(`max_tokens`)를 남겨 두세요.

  | 모델 컨텍스트 | 권장 `max_prompt_bytes` | 대략 넣을 수 있는 자료 |
  |---|---|---|
  | 8K 토큰 | 권장하지 않음 | 지시문(약 5KB)만으로 거의 참 |
  | 16K 토큰 | 20,000 | A4 3~4쪽 |
  | 32K 토큰 | 40,000 | A4 10쪽 안팎 |
  | 128K 토큰 | 150,000 | A4 40쪽 안팎 |

  자료가 이보다 크면 화면에 "자료가 너무 깁니다"가 나옵니다. 덜 중요한 자료를 빼거나 나눠서 분석하세요.
- **정밀 분석**: 3단계의 "정밀 분석"을 체크하면 `model_precise`에 적은 모델을 씁니다.
- **추론형 모델**: 답 앞에 `<think>…</think>`를 붙이는 모델도 그 부분은 자동으로 무시합니다. 답에 ```json 울타리나 설명 문장이 붙어도 JSON 부분만 읽습니다.

### 4.7 여러 사람이 함께 쓰려면

기본값은 이 PC(`127.0.0.1`)에서만 접속됩니다. 부서 서버 한 대에 띄워 여럿이 쓰려면 `server.host`를 `"0.0.0.0"`으로 바꾸면 되지만, 그러면 같은 망의 누구나 이 서버를 통해 사내 LLM을 부를 수 있습니다. 이 경우는 운영 배포에 해당하므로 **정보보호 검토를 먼저 받으세요**(접근 통제, HTTPS, 접속 기록 등).

### 4.8 Claude API로 연결하기

인터넷이 되는 PC에서 Claude API로 분석합니다. claude.ai에 로그인하지 않아도 되고, 사용량은 API 키의 조직에 청구됩니다.

1. Claude API 패키지를 설치합니다(한 번만).

   ```bash
   pip install anthropic
   ```

2. `settings.example.json`을 복사해 `settings.json`을 만들고 `llm` 부분을 이렇게 고칩니다.

   ```json
   "llm": {
     "provider": "anthropic",
     "api_key": "sk-ant-..."
   }
   ```

   - **API 키 넣는 곳**: `settings.json`의 `llm.api_key`. 파일에 두기 싫으면 비워 두고 환경변수 `ANTHROPIC_API_KEY`에 넣습니다(Windows: `set ANTHROPIC_API_KEY=sk-ant-...` 후 같은 창에서 실행).
   - `settings.json`은 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다. 키를 다른 파일이나 메일에 붙여 넣지 마세요.
   - `model`을 비워 두면 `claude-sonnet-5-5`(Claude Sonnet 5.5)를 씁니다.

3. 연결을 시험하고 실행합니다.

   ```bash
   python serve.py --check
   python serve.py
   ```

   화면 오른쪽 위 배지가 **Claude API 연결됨 · claude-sonnet-5-5**로 바뀌면 됩니다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| `model` | `claude-sonnet-5-5` | 다른 모델을 쓰려면 이름을 적습니다(예: 더 꼼꼼한 분석은 `claude-opus-5-5`) |
| `effort` / `effort_precise` | `high` / `xhigh` | 생각의 깊이. 3단계 '정밀 분석'을 체크하면 `effort_precise`를 씀. 높을수록 꼼꼼하지만 느리고 비용이 늘어남 |
| `max_tokens` | 64000 | 한 번에 받을 최대 출력. 응답이 끊기면 늘림 |
| `max_prompt_bytes` | 1,500,000 | 한 번에 보낼 최대 크기(약 50만 자) |
| `refusal_fallback` | `true` | Claude가 안전상 거절하면 서버가 다른 모델로 이어서 처리 |
| `timeout_sec` | 300 | 큰 자료는 몇 분 걸릴 수 있음. 시간 초과가 나면 늘림 |

> **보안**: Claude API는 외부 서비스입니다. 민감정보는 가린 뒤 보내지만, 실제 업무 자료는 기관의 「안전한 AI 사용 지침」에 따라 허용된 경우에만 넣으세요. 내부 자료는 사내 LLM(4.1~4.7)을 쓰세요.

### 4.9 웹에 올려 URL로 쓰기(Render)

심사위원처럼 설치 없이 **URL만으로 Claude API 분석까지** 쓰게 하려면 serve.py를 웹 호스팅에 올립니다. GitHub Pages 같은 정적 호스팅은 API 키를 숨길 수 없어 쓸 수 없습니다. 저장소에 Render 설정(`render.yaml`)이 들어 있습니다.

1. render.com에 GitHub 계정으로 가입합니다.
2. **New → Blueprint**를 누르고 이 저장소를 고릅니다(비공개 저장소면 Render에 접근 권한을 줍니다).
3. 설정을 읽은 뒤 값 두 개를 물어봅니다.
   - `ANTHROPIC_API_KEY`: Claude API 키 **(키는 여기에만 넣습니다)**
   - `REQAI_ACCESS_CODE`: 심사용 접속 코드(예: 짧은 영문·숫자). 비워 두면 코드 없이 누구나 AI 분석을 쓸 수 있습니다.
4. **Apply**를 누르면 몇 분 뒤 `https://allweneed-xxxx.onrender.com` 같은 주소가 생깁니다. 이 주소와 접속 코드를 심사위원에게 전달합니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `REQAI_LLM_PROVIDER` | `anthropic` | Claude API 사용 |
| `REQAI_LLM_MODEL` | `claude-sonnet-5-5` | 쓸 모델 |
| `ANTHROPIC_API_KEY` | (직접 입력) | Claude API 키 |
| `REQAI_ACCESS_CODE` | (선택) | 정하면 AI 분석 화면에서 이 코드를 넣어야 분석됨. 예시 결과 체험은 코드 없이 가능 |
| `REQAI_LIMIT_PER_IP_HOUR` | 40 | 한 사람(IP)이 1시간에 부를 수 있는 AI 호출 수(분석 1회 = 2호출) |
| `REQAI_LIMIT_PER_DAY` | 400 | 하루 전체 AI 호출 수. 넘으면 다음 날까지 AI 분석만 막힘 |

- **비용 보호**: 위 한도와 함께 Anthropic Console의 **Limits**에서 월 사용 한도를 꼭 정해 두세요. 주소가 퍼져도 그 이상은 청구되지 않습니다.
- **무료 요금제**는 15분 동안 접속이 없으면 잠들어, 다음 첫 접속에 1분 정도 걸립니다. 심사 기간에는 유료(Starter) 요금제로 바꾸거나, 심사 직전에 한 번 열어 깨워 두세요.
- 키를 바꾸거나 코드를 바꾸려면 Render 화면의 **Environment**에서 고치면 자동으로 다시 시작합니다.
- serve.py는 자료 본문과 AI 답을 서버에 남기지 않습니다. 다만 심사위원이 넣은 자료는 Claude API로 전송되므로, 실제 업무 자료 대신 가상 자료로 시연하도록 안내하세요.

## 5. 사용법

화면 위의 5단계를 차례로 진행합니다. 처음 열면 가상 예시 자료가 들어 있어 **예시 결과 바로 보기**로 바로 체험할 수 있습니다. 내 자료로 하려면 **지우고 내 자료 넣기**를 누릅니다.

### 5.1 자료 입력

- **붙여 넣기**: 각 칸(고객 니즈 · 회의 내용 · 참고 문서)의 **+ 직접 입력**
- **파일 올리기**: 칸마다 파일을 고르거나 끌어다 놓기. PDF, Word(.docx), Excel(.xlsx/.xls), PowerPoint(.pptx), 한글(.hwpx), TXT·MD·CSV·EML
  - .hwp는 한글에서 HWPX나 PDF로 저장해 올리세요. 스캔 이미지 PDF는 글자를 읽지 못합니다.
- **폴더째 끌어다 놓기**: 위쪽 큰 칸에 폴더(또는 여러 파일)를 놓거나 **폴더 선택**을 누릅니다.
  - 하위 폴더까지 모두 읽습니다.
  - 파일·폴더 이름으로 구분을 정합니다. 이름에 `회의·미팅·녹취·협의·회신`이 있으면 **회의 내용**, `요청·요구·니즈·문의·민원·건의·VOC·메일`이 있거나 .eml이면 **고객 니즈**, 나머지는 **참고 문서**입니다.
  - 구분이 틀리면 자료 카드의 구분 선택 상자에서 바꿉니다.
  - 숨김 파일, 임시 파일(`~$`로 시작), 지원하지 않는 형식(이미지 등)은 건너뛰고, 결과를 알림으로 보여 줍니다. 30MB가 넘는 파일도 건너뜁니다.
  - 폴더를 이렇게 나눠 두면 자동 분류가 정확해집니다.

    ```
    가맹점포털_개선/
    ├─ 고객요청/   요청메일_1006.eml, 협회_건의사항.pdf
    ├─ 회의록/     1차_회의록.docx, 2차_회의록.hwpx
    └─ 참고/       현행_기능개요.pdf, 화면목록.xlsx
    ```

### 5.2 민감정보 가리기

자동으로 찾은 민감정보와 바뀔 토큰이 왼쪽에 나옵니다. 체크를 풀면 그 값은 원문 그대로 AI에 갑니다(점선 표시). 기관명, 사업명처럼 더 가릴 말은 **직접 가릴 단어**에 추가합니다. 오른쪽 미리보기가 AI에 실제로 가는 내용입니다.

> 자동 탐지는 규칙 기반입니다. 직위 없이 쓴 이름, 주소, 차량번호 등은 못 찾을 수 있으니 미리보기를 꼭 확인하세요.

### 5.3 AI 분석

**AI로 분석 시작**을 누릅니다. 요구사항 추출(1회)과 누락·충돌 점검(1회), 두 번 AI를 부릅니다. 보통 30초~2분, 사내 LLM 성능에 따라 더 걸릴 수 있습니다.

### 5.4 검토·점검

| 탭 | 내용 |
|---|---|
| 요구사항 | 행을 누르면 상세, AS-IS/TO-BE, 검수 기준, **근거 문장**, **AI 판단 근거**가 나옵니다. 고칠 것은 **수정**, 확인한 것은 **확정** 체크. 확신도가 낮은 항목에는 `확인` 표시가 붙습니다. |
| 회의 분석 | AS-IS → TO-BE 표, 결정사항, 미결사항, 후속 조치 |
| 누락·충돌 점검 | 빠진 항목, 서로 다른 의견, 모호한 표현과 제안. 처리하면 **해결됨** 체크 |
| 확인 질문 메일 | 물어볼 사람별 메일 초안. **메일 내용 복사**는 가린 값을 원래 값으로 채워 복사합니다 |
| 회신 반영·이력 | 회신이나 추가 자료를 넣고 **요구사항에 반영**. 바뀐 요구사항에 `변경`/`추가` 표시가 붙고 이력이 남습니다 |

AI 판단 근거는 세 가지를 보여 줍니다.

- **왜 뽑았나**: 어느 자료의 어떤 요청·발언에서 나왔는지
- **유형·우선순위**: 왜 그 유형과 우선순위로 정했는지
- **수용 여부 판단**: 회의 결정, 담당자 의견, 참고 문서 중 무엇을 근거로 판단했는지
- **확신도**: 높음(명시적 결정 있음) · 보통(발언에서 추론) · 낮음(근거 약함, 사람 확인 필요)

### 5.5 문서 만들기

왼쪽 **양식**에서 다섯 가지 중 하나를 고릅니다. 오른쪽에 그 양식의 미리보기와 내려받기 버튼이 나옵니다.

| 양식 | 편집 | 내려받기 |
|---|---|---|
| 개발요청서(표준) · RFP 요구사항 정의표 · 간이 요구사항 목록 | 목차와 열을 켜고 끄고, 이름을 바꾸고, 순서를 옮김(이 브라우저에 저장) | Word · Excel · Markdown |
| 품의문(한글) | 사내 문서 작성 표준으로 고정. 문서 정보(건명·부서·작성자·대상 시스템)만 입력 | 한글(.hwpx), 5.6 |
| 요구사항명세서(Excel) | 사내 요구사항명세 양식으로 고정. 문서 정보(건명·작성자·작성일)만 입력 | Excel(.xlsx), 5.7 |

AI 판단 기록(.md)은 어느 양식에서나 내려받을 수 있습니다.

| 내려받기 | 내용 |
|---|---|
| Word | 표지 정보, 요구사항 표, 상세, 결정·미결, 점검 결과, 참고 자료, 변경 이력 |
| Excel | 요구사항, 추적표(요구사항 ↔ 출처), 점검결과, 확인질문, 변경이력 시트 |
| Markdown | Word와 같은 내용 |
| **AI 판단 기록(.md)** | 판단 과정 전체 기록([6장](#6-ai-판단-기록md-읽는-법)). 4단계 화면 위쪽에서도 받을 수 있습니다 |

**가린 값을 원래 값으로 채워서 내보내기**를 끄면 `[이름-1]` 같은 토큰 상태로 내보냅니다. 외부에 공유할 때 쓰세요.

### 5.6 품의문(.hwpx)

한글 2014 이후 버전에서 열립니다. 내용은 분석 결과에서 자동으로 채우고, 모양은 사내 한글 문서 작성 표준을 따릅니다.

| 항목 | 적용 내용 |
|---|---|
| 용지 | A4, 위 20mm · 아래 10mm · 좌우 20mm, 머리말·꼬리말 10mm |
| 글꼴 | 휴먼명조(제목·대제목·중제목은 굵게), 장평 100% · 자간 0% |
| 크기 | 문서 제목 22pt, 대제목 16pt, 중제목 15pt, 내용 14pt, 표 제목 14pt(밑줄), 표 내용 12pt, 주석 12pt |
| 제목 | 본문 1쪽 상단 제목 상자(높이 15mm, 위아래 양단선 1mm) |
| 항목 체계 | 1. → 가. → □ → ○ → -, 하위 항목은 1칸 들여씀 |
| 간격 | 줄 간격 160%(주석 130%, 표 110%), 문단 사이는 표준의 빈 줄 크기(20 · 16 · 14 · 6pt) |
| 표 | 0.1mm 검정 실선, 양 끝 세로선 없음, 셀 높이 7mm, 셀 여백 좌우 1.8mm · 상하 0.5mm, 첫 행만 음영 |
| 쪽 번호 | 가운데 아래 "- 1 -" |
| 끝맺음 | "붙임  요구사항명세서 1부.  끝." |

구성: 1. 추진 배경 → 2. 요청 개요(건명·부서·대상 시스템·내용·요구사항 수) → 3. 주요 요구사항(요구사항 목록 표, 조건부 수용·불가 사항) → 4. 협의 결과 및 향후 조치(결정사항·미결사항·후속 조치 표). 요청 부서와 대상 시스템은 왼쪽 **문서 정보**에 입력한 값을 씁니다.

> 휴먼명조는 한글과 함께 설치됩니다. 휴먼명조가 없는 PC에서는 한글이 비슷한 글꼴로 바꿔 보여 주고, 앱의 미리보기는 HY신명조 → 함초롬바탕 → 나눔명조 → 바탕 순으로 비슷한 명조를 씁니다. 결재란·문서번호 같은 전자결재 항목은 결재 시스템에서 붙입니다.

### 5.7 요구사항명세서(.xlsx)

사내 양식과 같은 배치로 만듭니다.

| 위치 | 내용 |
|---|---|
| 1행 | 관련개발요청(건명, B~D 병합) · 작성자 · 작성일 (노란 칸이 항목 이름) |
| 3행 | 머리글: 요구사항 ID · 유형 · 품질속성 · 요구사항명 · 상세설명 · 긴급도 · 난이도 · 출처 (필터, 틀 고정) |
| 4행부터 | 요구사항 한 줄씩. 상세설명에 수용 여부 조건과 검수 기준, 출처에 자료 ID·구분·발언자 |
| 목록 | 유형 · 품질속성 · 긴급도 · 난이도 칸은 목록에서 고르도록 설정 |

- **품질속성**은 ISO/IEC 25010 품질 특성(기능적합성 · 성능효율성 · 호환성 · 사용성 · 신뢰성 · 보안성 · 유지보수성 · 이식성 · 해당 없음) 중 하나를 AI가 고릅니다.
- **긴급도**는 기존 우선순위(상·중·하), **난이도**는 AI가 개발 담당 의견과 연동 범위로 추정한 구현 난이도(상·중·하)입니다.
- 둘 다 4단계 요구사항 **수정**에서 바꿀 수 있습니다.

## 6. AI 판단 기록(.md) 읽는 법

나중에 "이 요구사항은 왜 이렇게 정리됐나"를 추적할 수 있도록 한 번의 작업을 처음부터 끝까지 기록한 문서입니다. 감사·인수인계·이의 제기 대응에 씁니다.

| 장 | 내용 | 확인할 것 |
|---|---|---|
| 머리 | 만든 일시, 도구 버전, 분석 방식(사내 LLM 모델 이름 / Claude / 예시 모드) | 어떤 AI가 판단했는지 |
| 1. 처리 순서 | 자료 입력 → 가리기 → 추출 → 점검 → 사람 검토 → 문서 | |
| 2. 입력 자료 | 자료 ID, 구분, 제목, 글자 수, 파일 이름 | 빠진 자료가 없는지 |
| 3. 민감정보 보호 조치 | 유형별로 가린 개수, 가리지 않고 보낸 개수 | "가리지 않음"이 있으면 의도한 것인지 |
| 4. AI 호출 기록 | 호출 시각, 단계, 모델, 보낸 크기, 받은 글자 수, 걸린 시간, 성공/실패 | 실패한 호출, 비정상적으로 짧은 응답 |
| 5. 요구사항별 판단 근거 | 요구사항마다 추출·분류·수용 판단 근거, 확신도, 사람 검토 상태, 근거 문장(원문 인용), 변경 이력 | 확신도 "낮음", 근거 문장 없음, "검토 중"으로 남은 것 |
| 6. 점검 판단 | 빠진 항목·상충 의견·모호 표현을 왜 지적했는지와 처리 상태, 확인 질문 | "확인 필요"로 남은 것 |
| 7. 전체 변경 이력 | 최초 분석, 회신 반영, 담당자 직접 수정이 시간순으로 | 누가(AI/담당자) 무엇을 바꿨는지 |
| 8. 유의사항 | AI 결과의 한계 | |
| 부록 | AI에 준 지시문 전문 | 같은 지시로 다시 실행해 비교할 때 |

- 원래 민감정보 값은 3장에 남기지 않습니다. 본문은 내보내기 설정(가린 값 채우기 켜기/끄기)에 따릅니다.
- 같은 자료라도 모델이나 실행 시점에 따라 결과가 조금 달라질 수 있습니다. 기록은 그 실행의 판단 과정입니다.

## 7. 보안과 개인정보

- 자료는 브라우저 메모리에만 있고, 창을 닫으면 사라집니다. 서버나 브라우저 저장소에 자료를 저장하지 않습니다(양식 설정과 작성자·부서 이름만 브라우저에 저장).
- AI에는 민감정보를 가린 내용만 갑니다. 원래 값으로 되살리는 일은 브라우저 안에서만 일어납니다.
- serve.py는 자료와 AI 답을 기록하지 않습니다. 사내 LLM 쪽에서 요청을 기록하는지는 LLM 운영 부서에 확인하세요.
- `settings.json`에는 주소·키가 들어가므로 GitHub 등에 올리지 마세요(`.gitignore`에 들어 있음).
- 이 프로그램은 프로토타입입니다. 실제 업무 자료에 쓰거나 여러 사람이 쓰는 서비스로 운영하기 전에 정보보호 검토를 받으세요.

## 8. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `python`을 찾을 수 없다고 나옴 | Python을 설치하고 PATH에 추가하세요. Windows는 `py serve.py`도 됩니다. |
| 배지가 **예시 모드 · AI 미연결** | 파일로 바로 열었거나(방법 A), `settings.json`의 `provider`가 `"none"`입니다. serve.py로 열었는지, 주소창이 `http://127.0.0.1:8080`인지 확인하세요. |
| 배지가 빨간 **사내 LLM(또는 Claude API) 연결 안 됨** | 배지에 마우스를 올려 이유를 봅니다. `python serve.py --check`로 시험하세요. 주소(`base_url` 끝이 `/v1`인지), 방화벽, 사내 프록시(`use_system_proxy`)를 확인합니다. |
| "인증을 거부했습니다(HTTP 401/403)" | `api_key` 또는 환경변수 `REQAI_LLM_API_KEY`, `extra_headers`를 확인하세요. |
| `CERTIFICATE_VERIFY_FAILED` | 사내 인증서 파일 경로를 `ca_bundle`에 넣으세요. `verify_tls: false`는 시험할 때만 씁니다. |
| "AI 응답을 표로 정리하지 못했습니다" | 모델이 JSON 형식을 지키지 못했습니다. 다시 시도하거나 더 큰 instruct 모델로 바꾸세요. `--check`의 3)을 확인하세요. |
| "자료가 너무 깁니다" | `max_prompt_bytes`를 모델 컨텍스트에 맞게 늘리거나 자료를 줄이세요([4.6](#46-모델과-크기-고르기)). |
| "사내 LLM 응답이 너무 늦습니다" | `timeout_sec`을 늘리세요(예: 600). |
| 결과가 잘리거나 요구사항이 너무 적음 | `max_tokens`을 늘리세요(예: 16384). 모델 최대치를 넘지 않게 합니다. |
| PDF·Word·Excel 파일을 못 읽음 / Word·Excel 내려받기 실패 | 폐쇄망이면 `vendor` 폴더와 `assets.offline: true`를 확인하세요. 실행 창에 vendor 경고가 나오면 [3.1](#31-인터넷-pc에서-준비)을 다시 하세요. |
| 폴더를 놓았는데 일부만 들어옴 | 알림에 건너뛴 파일과 이유가 나옵니다. 이미지·HWP·DOC는 읽지 못합니다. |
| 포트가 이미 사용 중 | `python serve.py --port 9000` |

## 9. 개발자 참고

### 9.1 구조

| 파일 | 역할 |
|---|---|
| `src/shell.html` | 화면 틀과 CSS |
| `src/sample.js` | 가상 예시 자료와 미리 분석한 결과 |
| `src/engine.js` | 설정(`CFG`), 민감정보 가리기, 파일 읽기, AI 지시문, 응답 정리, 문서·Excel·판단 기록 생성 |
| `src/forms.js` | 품의문(HWPX 직접 생성: `buildPumuiBlocks` 내용, `hwpxHeader` 글자·문단·테두리 모양, `hwpxSection` 본문), 요구사항명세서(`SPEC_COLS` 열 정의, xlsx 직접 생성) |
| `src/app.js` | 화면 단계, 이벤트, AI 연결 감지(`detectAI`), AI 호출(`askJSON` → `askLocal` 또는 claude.ai), 폴더 읽기 |
| `serve.py` | 정적 파일, `/config.js`(설정 전달), `/api/health`, `/api/llm`(사내 LLM 중계) |

AI 연결은 이 순서로 고릅니다: `/config.js`에 사내 LLM 설정이 있으면 사내 LLM → claude.ai 안에서 열렸으면 Claude → 둘 다 아니면 예시 모드.

### 9.2 고친 뒤 빌드

`src/`를 고쳤으면 다시 빌드합니다. `settings.json`만 고쳤으면 빌드할 필요 없이 serve.py만 다시 켜면 됩니다.

```bash
python build.py
```

### 9.3 AI 지시문 바꾸기

`src/engine.js`의 `promptAnalyze`(추출·분류), `promptCheck`(점검·질문), `promptUpdate`(회신 반영)입니다. 응답 JSON 형식을 바꾸면 `normalizeReq`, `normalizeResult`도 함께 고치세요. 작은 모델에서 결과가 불안정하면 지시문을 짧게 하고 예시를 늘리는 것이 효과적입니다.
